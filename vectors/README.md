# Test vectors

Versioned, first-class artifacts of the spec: a conforming implementation in any language must reproduce them. Vector bugs are spec bugs — report them as such.

| File | Covers | Spec |
|---|---|---|
| [`crypto-v0.1.json`](crypto-v0.1.json) | hash_to_curve, blind/unblind round-trip, blind signatures, DLEQ (issuance-side and proof-side) | [PIP-00](../PIP-00.md) |

## Provenance

The `cashu_compat` sections reproduce upstream [Cashu NUT-00 and NUT-12 test vectors](https://github.com/cashubtc/nuts/tree/main/tests) verbatim — picocash's crypto layer is byte-compatible by design, and passing them demonstrates that. The `picocash` sections are generated by [`packages/crypto/scripts/generate-vectors.ts`](https://github.com/picocash/picocash/blob/main/packages/crypto/scripts/generate-vectors.ts) with fixed (published) secrets, blinding factors, and DLEQ nonces so they are fully deterministic.

**Never** reuse any secret, blinding factor, or nonce from these files in a real wallet or mint.
